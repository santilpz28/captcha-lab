Solver readout

server-side CV
Run “Auto-solve (CV)” to see the matcher output. The solver correlates the dragged sprite against the background with a masked normalised cross-correlation (FFT). A hit means the template match found the gap — i.e. the challenge is machine-solvable.

How this works

read me

Generator. A procedural photo-like background is built from gradients, blobs and two octaves of noise. A jigsaw piece is knocked out of it; the piece sprite is cut from that exact region, so the hole's interior pixels stay pristine.

Solver. The sprite is correlated against the background with a masked NCC over FFT. Because the sprite is literally the gap's texture, the correlation peaks at exactly 1.0 on the true position. This is the attacker view — if it hits, the CAPTCHA is weak.

Behaviour profiler. The verify endpoint scores the drag trace: humans wobble, overshoot and reverse; bots teleport in one step. It also records how many real pointer events the browser saw, so a trace forged over the API is caught even when its path looks human. Attempts scoring below the threshold are rejected with behaviour_rejected; in LAB mode they are logged but allowed through, so the tester can measure both numbers.

What this is not. A production CAPTCHA. There is no HMAC-signed answer, no server-side pixel-perfect tolerance tuning, and no rate limiting. It is a bench for measuring and reasoning about slider-CAPTCHA resistance.
